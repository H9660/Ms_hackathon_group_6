# M7: Step 7, Campus Schedule, Final Validation and Pitch

## What I built
- **`ui/schedule.py`**: a *Campus schedule* page for everyone, reached from the sidebar with no name needed.
  - A day timeline with one row per venue, so free venues are visible, coloured by state (confirmed, pending, blocked).
  - A legend, hover tooltips and a table listing the same commitments, so state never depends on colour alone.
  - A "free all day" list, a toggle that also shows rejected and cancelled requests, and a table of all confirmed events.
- **`tests/test_acceptance.py`**: 12 end-to-end demo scenarios (S1–S12) plus 2 schedule tests. Each clicks through the real app in one session, switching roles.
- **`docs/TEST_SCENARIOS.md`**: the scenario table with results from the final run, coverage by layer, and the extra checks done during development.
- **`docs/PITCH.md`**: the two-slide consulting pitch.
- **README**: scope, excluded features, trade-offs, known limitations and next steps; pinned `altair` and `pandas`, which the schedule imports.
- **Corrections:** fixed the test counts in the M5 and M6 notes to match `pytest --collect-only`.

## Business rule I own
**Visibility: the campus can see each venue's commitments.** The schedule shows only what holds a venue (PENDING, CONFIRMED and blocks), using the same definition as the conflict check. What people see is exactly what blocks a booking. Released requests are hidden unless asked for.

## Assumption / trade-off
- **A24:** the schedule is visible to everyone and needs no name. Event titles and organisers are public on campus.
- **Trade-off:** the timeline shows a single day. A week view would help planning, but a day view matches how conflicts are checked and stays readable.

## How I validated it
- **Validated the previous step:** pulled Step 6, ran `pytest -q` (168 passed), and checked the inbox flow by approving as Reviewer, then reading as Requester.
- **Final full run:** `pytest -q -W default` → **182 passed, no warnings**. S1–S12 all pass, recorded in `TEST_SCENARIOS.md`.
- **Schedule tests** check the actual table contents: 4 Aug shows 1 CONFIRMED and 1 BLOCKED, Main Auditorium is listed as free all day, cancelled events appear only with the toggle, and an empty day renders without errors.
- **Chart colours** use the reserved status palette (good / warning / critical), with a legend, tooltip and table, so colour is never the only signal.
