# M1: Step 1, Foundation

## What I built
- `cems/models.py`: `Status` enum, `ACTIVE_STATUSES`, `EVENT_TYPES`, the `Venue` / `Event` / `VenueBlock` / `AuditEntry` dataclasses, and datetime helpers.
- `cems/db.py`: SQLite schema (venues, events, venue_blocks, audit_log, plus indexes), `get_conn`, `init_db`, the `transaction()` context manager, and `clear_all`.
- `cems/repository.py`: data access for venues, events, blocks and the audit log.
- `cems/seed.py`: the brief's initial campus data, idempotent `seed()`, `reset_db()`, and the CLI (`python -m cems.seed [--reset]`).
- Test suite foundations: `conftest.py` fixtures plus model, DB, seed and repository tests (34 tests).
- `README.md`, `CLAUDE.md`, `requirements.txt`, `pyproject.toml`, `.gitignore`.

## Business rule I own
**A venue is held only by PENDING or CONFIRMED events** (`ACTIVE_STATUSES`).
Rejection and cancellation release the venue just by changing the status. No row is deleted, so the history is kept.

## Assumption / trade-off
- Datetimes are stored as minute-precision ISO text (`YYYY-MM-DDTHH:MM`). This text sorts in time order, which keeps the overlap SQL simple. The cost is that seconds and time zones are not supported, which is acceptable for room booking on a single campus.
- The database also has `CHECK` constraints (status values, `end > start`, `capacity > 0`, `attendees > 0`) as a last line of defence. User-facing messages still come from `rules.py` (Step 2).

## How I validated it
- `pytest -q` → 34 passed. The seed tests compare every venue, confirmed event and block against the brief's table.
- Ran `python -m cems.seed` twice (the second run was a no-op), then `--reset`, and inspected the results through the repository.
- Tested rollback: an exception inside `transaction()` leaves no partial rows, including when transactions are nested.

## AI suggestion I corrected
The first draft of `seed()` set `venue_id` directly on the module-level seed dataclasses. That silently changes shared global state every time it runs, for example on `reset_db`. I replaced it with `dataclasses.replace(...)` so the seed data is never modified.
